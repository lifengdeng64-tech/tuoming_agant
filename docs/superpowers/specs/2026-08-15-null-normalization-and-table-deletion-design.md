# 空值统一与工作表级删除设计

## 目标

修复 Excel 导入中空值文本与数值混合导致的 Arrow/Parquet 类型转换失败；允许用户在一次 Excel 上传生成多个工作表数据制品后，单独删除某个工作表及其下游分析，而不删除同一文件的其他工作表或本地加密原件；同时简化上传确认按钮文案。

## 空值统一规则

Excel 和 CSV 解析完成、敏感字段检测与脱敏开始前，统一规范缺失值。以下内容转换为真正的缺失值 `pd.NA`：

- 原始空单元格，以及 Pandas 已识别的 `NaN`、`NaT` 和 `None`；
- 只包含空白字符的字符串；
- 忽略大小写且去除首尾空白后等于 `NaN`、`N/A`、`NULL` 或 `None` 的字符串。

`0`、`-`、“无”、“未完成”等可能具有业务语义的值不视为空值。规范化发生在敏感字段扫描之前，因此空值不会被生成脱敏 Token，写入 Parquet 后仍保持为空，授权还原和导出后也保持为空。

规范化必须同时应用于预览和正式分块导入，保证用户确认时看到的数据语义与最终制品一致。数值列中的空值不能迫使整列变为字符串，字符串列中的合法文本不得被数值化。

## 工作表级删除范围

工作表删除入口以单个 `dataset_versions.id` 及其源数据 `artifact_id` 为目标，而不是以整个 `files.id` 为目标。一次删除覆盖：

1. 目标工作表的数据集版本和源 Parquet 制品；
2. 以该制品为祖先的全部下游分析结果制品；
3. 引用上述制品的分析运行、计划版本和执行尝试；
4. 聊天消息中指向被删除制品的附件引用。

删除不会影响同一 Excel 的其他工作表、加密原始文件、文件记录、聊天文字或租户级 Token 映射。如果逻辑数据集还有其他版本，则保留数据集；没有任何剩余版本时才删除空的数据集记录。

## 删除交互

“数据 → 数据集与版本”区域把每个工作表版本显示为独立条目，并提供“删除”按钮。第一次点击只进行影响分析并显示：

- 工作表名称和版本；
- 数据行数；
- 将删除的数据制品数量；
- 关联分析运行和下游结果数量。

只要存在关联分析或下游制品，用户必须勾选“我了解关联分析和结果也会删除”，最终确认按钮才可用。取消不产生持久化变化。成功后刷新列表并显示删除摘要；失败时保留原数据并显示可操作错误。

完整文件删除入口继续保留，用于删除加密原件及该上传的所有工作表。两个入口必须使用不同文案，避免混淆“删除工作表”和“删除整个文件”。

## 原子性与安全

工作表删除复用现有文件删除的安全模式，但只处理选中工作表的闭包：

1. 影响分析只读，并同时约束 `tenant_id`、`workspace_id` 和目标数据集版本；
2. 所有待处理路径必须来自数据库，并验证为数据目录内的普通受管文件；
3. 先把目标 Parquet 文件移动到数据目录内唯一的 `.trash/<operation-id>/`；
4. 在单个 `BEGIN IMMEDIATE` 事务内删除相关计划、尝试、运行、字段策略、数据集版本和制品，并把聊天附件引用置空；
5. 同一事务写入不含原始数据的 `dataset_version_deleted` 审计事件；
6. 事务失败时恢复文件，事务成功后清理此次回收目录。

加密原始 Excel 始终保留在原位置，除非用户另行执行完整文件删除。

## 重复上传与恢复

重新上传内容哈希相同的 Excel 时，已存在的工作表版本仍按重复项跳过；先前被单独删除且当前缺失的工作表允许重新生成。重新生成使用本次上传内容或保留的加密原件，沿用正常的敏感字段确认和脱敏流程，不直接恢复旧 Parquet 文件。

## 上传按钮文案

上传确认按钮固定显示“确认添加”，不再根据待上传文件数量生成“确认并追加 N 个文件”。待处理文件数量继续由上传区和文件卡片表达。

## 测试与验收

- 解析测试覆盖真正空单元格、空白字符串和大小写不同的 `NaN`、`N/A`、`NULL`、`None`。
- 导入测试验证数值列混入空值文本后能写入 Parquet，非空数值保持数值类型，读取结果为空值而不是字符串。
- 脱敏测试验证空值不创建 Token，授权还原后仍为空。
- 仓库和服务测试覆盖无下游工作表删除、有下游分析的级联删除、多版本保留、聊天附件解绑、跨租户拒绝和事务回滚。
- 文件测试验证只删除目标工作表及其下游 Parquet，不移动加密原件或同文件其他工作表。
- 重复上传测试验证被删除工作表可重新生成、仍存在工作表不重复添加。
- UI 测试覆盖工作表级删除入口、影响摘要、二次确认、取消、成功刷新，以及上传按钮固定文案“确认添加”。
- 最终运行全量 pytest、Ruff、compileall 和 `git diff --check`。

## 非目标

本次不自动忽略空白、隐藏或仅一行的工作表，不改变用户在分析页选择主数据源的方式，不修改加密原始 Excel，不回收共享 Token 映射，也不新增图表或可视化功能。
