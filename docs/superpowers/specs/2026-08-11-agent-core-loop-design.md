# Agent 核心闭环设计

## 目标

把当前“一次规划后立即执行”升级为可恢复、可审计、需要人工确认的闭环：

`规划 -> 预览 -> 用户确认 -> 本地执行 -> 确定性质量校验 -> 完成/修复`

本阶段只覆盖核心闭环，不加入图表、模板、长期记忆或 token 成本统计。

## 安全原则

- 模型只生成 `AnalysisPlan` 白名单操作，不执行代码。
- 每一个计划版本都必须由用户明确确认后才能执行。
- 可修复的业务错误和质量错误允许产生新计划，默认最多 3 次；修复计划仍需确认。
- 安全策略拒绝、越权访问、危险表达式绝不自动修复，运行立即进入 `security_blocked`。
- 候选结果先在内存中执行并校验，通过后才保存为制品。

## 持久化模型

- `analysis_runs`：一次用户请求的状态、修复计数、最终制品和错误分类。
- `analysis_plan_versions`：初始、反馈改写或错误修复产生的每个计划版本及用户决策。
- `analysis_attempts`：每次实际执行、质量报告、错误类型和关联制品。

状态机主路径为：

`planning -> awaiting_confirmation -> executing -> validating -> completed`

终止或分支状态包括：`rejected`、`security_blocked`、`failed`。业务/质量错误在修复额度内生成下一版计划并回到 `awaiting_confirmation`。

## 质量校验

确定性失败项：

- DataFrame 可序列化并可读回。
- 输出列名非空且唯一。
- lineage 只引用真实输出列。
- 数值列不存在正负无穷。

告警项不阻断保存：空结果、空值、合并结果异常放大、输出规模较大、仅截取/排序等非聚合结果。

## UI

- 用中文摘要展示数据源、结果名称和每一步操作，不要求用户编辑 JSON。
- 提供“确认并执行”“拒绝”“提交修改意见”。
- 展示版本、状态、修复次数、失败原因和质量告警。
- 刷新或进程重启后从 SQLite 恢复待确认计划和历史状态。

## 错误分类

- `SecurityPolicyViolation`：安全拒绝，禁止修复。
- `RepairableAnalysisError`：列不存在、类型转换失败、合并键不匹配、质量失败等，可修复。
- `TerminalAnalysisError`：模型不可用、持久化异常或达到修复上限，直接失败。
